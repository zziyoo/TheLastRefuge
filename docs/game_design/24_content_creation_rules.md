7. 设计平衡要求

每个新内容必须回答：

为什么存在？
解决什么问题？
带来什么代价？
与什么系统产生关系？
8. 禁止内容

禁止无意义地大量增加：

+5% 资源
+8% 资源
+10% 资源

如果三个内容只是换数字：

应该合并。

9. 事件设计

事件至少满足：

信息
选择
代价
结果

重大事件最好增加：

长期后果
10. 内容新增后的测试

Agent 必须同时提交：

内容定义
触发条件测试
正常路径测试
失败路径测试
极端条件测试
11. 不修改无关代码

内容 Agent 默认：

只修改对应 Data / Content 文件。

除非发现核心系统无法支持目标需求。

12. 内容重复检查

新增内容必须检查：

同名
同效果
同事件结构
同奖励
同 ID

避免产生大量换皮内容。
