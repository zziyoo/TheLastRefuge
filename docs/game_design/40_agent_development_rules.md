《最后避难所》Agent 开发规范
1. 总原则

Agent 的职责：

在现有架构和设计规则内实现需求。

Agent 不应擅自修改游戏设计方向。

2. 开始任务前

必须阅读：

相关 game_design 文档
相关系统代码
相关 Data Definition
相关测试
3. 不允许自行修改核心设计

除非任务明确要求。

例如不得因为：

“这样更容易实现”

就自行改变：

60 天流程
资源消耗
肉鸽规则
角色机制
结局条件
4. 内容优先数据驱动

新增：

角色
事件
遗物
科技
建筑
物品
地点
派系

优先新增 Data。

不要为一个普通内容创建独立系统。

5. 修改核心系统前

必须确认：

现有系统是否已经支持
是否能通过扩展现有效果
是否会影响旧内容
是否需要测试
是否影响存档
6. 修改范围

默认：

只修改完成任务所需要的文件。

避免：

顺手重构大量无关代码。

7. GameState

不能在 UI 层直接随意修改。

必须通过：

Command
System
Effect

等正式流程修改。

8. 随机系统

所有影响游戏结果的重要随机：

必须经过统一 RandomSystem。

确保：

Seed 可复现。

9. 新增内容

必须检查：

ID 是否唯一
引用是否存在
数值是否合法
条件是否可达
效果是否可执行
是否有测试
10. 事件

新增事件必须：

有明确触发条件
有明确选项
有明确 Effect
有长期后果设计或明确说明

不能只写：

一段文字 + 随机奖励。

11. 肉鸽内容

新增遗物/强化必须说明：

所属标签
强度级别
正面效果
负面效果
联动
出现阶段
12. 存档

修改 Runtime State：

必须检查 SaveData。

修改存档结构：

必须更新 SaveVersion / Migration。

13. 测试

修改核心系统：

必须补充或更新测试。

新增内容：

至少测试正常路径和异常路径。

14. 完成任务时

Agent 应输出：

修改了什么
为什么修改
影响哪些系统
运行了哪些测试
是否存在未解决问题
15. 不允许隐藏问题

如果发现：

设计冲突
现有架构无法支持
存档兼容风险
测试失败

必须明确报告。

不得：

用临时绕过方案伪装成完整实现。

16. 不允许过度工程化

一个简单内容：

不应该引入一个大型框架。

优先使用：

已有系统、已有接口、已有数据结构。

17. 不允许为了通过测试修改测试结论

如果发现：

测试失败。

先修复代码或说明原因。

不能简单：

放宽测试条件来让测试通过。

18. Git 规范

每个逻辑明确的修改：

建议保持独立 Commit。

Commit 应能够说明：

实现什么
修复什么

避免：

一个 Commit 混合大量无关功能。

19. Code Review 自检

提交前至少检查：

是否破坏已有系统？
是否改变未授权规则？
是否有死循环？
是否可能 NaN / Infinity？
是否可能资源负数？
是否有空引用？
是否能正确读档？
是否能被 Seed 复现？
20. 最重要原则

Agent 可以提出设计改进建议，但不能未经允许把“建议”当成“需求”实施。

设计文档、任务描述和当前代码共同决定：

当前真正需要实现的行为。
